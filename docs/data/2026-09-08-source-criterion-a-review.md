# 채용 source 후보 기준 A 심사 기록

> 상태: 실측 확인 완료 / 수집기 구현 없음
>
> 기준일: 2026-09-08
>
> 관련 Jira: `S15P21E102-149`(수집기 2차, 종결) · `S15P21E102-94`(잡코리아 존치 판단) · `S15P21E102-161`(API 신청)
>
> 근거 기준: [잡코리아 존치 여부 판단 근거](2026-08-31-jobkorea-retention-decision.md) §4 기준 A

## 1. 왜 다시 확인했나

`-149`는 "후보 2종이 기준 A 미통과"로 종결됐으나, **어느 사이트를 어떤 근거로 탈락시켰는지가 어느 문서에도 남아 있지 않았다.** 판정만 있고 근거가 없는 상태였다.

`-94` §7 후속 과제 5번이 "각 source에 §4 기준 A를 동일하게 적용한다"를 남겨둔 항목이기도 하다. 이 문서가 그 기록이다.

적용 기준은 `-94` §4를 그대로 쓴다.

> **A. 수집 정당성** — 정식 수집 경로가 없거나 판례·약관상 금지되면 Coverage와 무관하게 제외
>
> 기준 A는 B·C보다 상위다. **A에 걸리면 B·C를 측정하지 않는다.**

기준 A는 **OR 조건**이다. `robots.txt`가 허용해도 약관이 금지하면 미통과다. 따라서 아래 두 사이트의 Coverage·공고당 기술 수는 측정하지 않았다.

## 2. 판정

| 후보 | 기준 A | 결정적 근거 |
|---|---|---|
| 게임잡 | **미통과** | 운영사가 잡코리아와 **동일 법인**. `-94`의 판례·소송 근거가 그대로 적용 |
| 링커리어 | **미통과** | 이용약관 제20조가 **크롤링·스크래핑을 명시적으로 금지** |
| 자소설닷컴 | **판정 불가** | 약관 페이지가 SPA라 본문을 확인하지 못했다. §5 |
| 잡알리오 | **해당 없음** | 같은 데이터의 공식 API가 있다. 크롤링 대상이 아니다. §6 |
| 공공데이터 채용 API | **통과** | 정식 경로 존재, **이용허락범위 제한 없음**. 다만 기준 B가 의심된다. §6 |

**`-149` 종결 판정은 유지한다.** 재확인 결과 원래 판정이 옳았고, 이제 근거가 있다.

기준 A를 통과한 후보가 하나 나왔다는 점이 이 표의 핵심이다. 게임잡·링커리어는 A에서
끊겨 더 볼 것이 없지만, 공공데이터 API는 **실제로 받아 보고 판단할 수 있는 상태**다.

## 3. 게임잡 — 잡코리아와 동일 법인

### 3.1 운영 주체

| 항목 | 실측값 |
|---|---|
| 회사명 | 웍스피어 유한책임회사 (Worxphere LLC) |
| 대표자 | 윤현준 |
| 사업자등록번호 | **110-81-34859** |
| 통신판매업 신고번호 | 2016-서울서초-0287호 |
| 직업정보제공사업 신고번호 | 서울청 제2016-11호 |

웍스피어는 **잡코리아가 창립 30주년에 변경한 사명**이다. 사업자등록번호가 동일하고, 웍스피어 공식 사이트가 잡코리아와 게임잡을 나란히 자사 서비스로 소개한다. Google Play 앱 패키지명도 `com.jobkorea.gamejob`이다.

즉 **게임잡을 크롤링하는 것은 잡코리아를 크롤링하는 것과 같은 법인을 상대로 하는 행위다.**

### 3.2 그래서 `-94` 근거가 그대로 적용된다

`-94`가 잡코리아를 제외한 근거는 사이트별 특성이 아니라 **법인 상대의 판례·소송 이력**이었다.

- 대법원 "웹사이트 무단 크롤링은 불법"
- "경쟁회사 채용정보 무단 크롤링해 게재하면 저작권 침해"
- 잡코리아 대리 저작권침해금지 소송 최종 승소
- 사람인에이치알이 잡코리아에 무단 크롤링 소송 **합의금 120억 지급**

같은 법인의 다른 도메인이라는 이유로 이 근거가 약해지지 않는다. 오히려 **직접 소송을 제기해 승소한 이력이 있는 당사자**다.

### 3.3 약관과 robots.txt

이용약관(`/Service_GJ/Provision_GG.asp`) 제17조가 "타인의 저작권을 침해하는 행위"와 "정보통신망법 등 관련법을 위반하는 행위"를 금지한다. 잡코리아가 무단 크롤링을 **저작권 침해로 구성해 승소한** 당사자라는 점과 함께 읽어야 한다.

`robots.txt`는 참고로 기록한다. **판정에는 영향이 없다**(OR 조건).

```text
User-agent: *
Disallow: /List_GG/  /Login/  /User/  /Text_User/
Disallow: /Text_Co/  /Project/  /Help/  /Corp/Person/Find
Sitemap: http://www.gamejob.co.kr/content/sitemap.xml
Sitemap: http://www.gamejob.co.kr/content/sitemap/AGI/sitemap.xml
Sitemap: http://www.gamejob.co.kr/content/sitemapindex.xml
```

공고 목록·상세 경로는 `Disallow`에 없고 Sitemap도 3개 공개한다. **`robots.txt`만 보면 허용으로 읽힌다.** 잡코리아 본체가 공고 상세 경로를 명시적으로 `Disallow`하는 것과 대조적이다. 그러나 기준 A는 `robots.txt` 단독 판정이 아니다.

### 3.4 공식 API

게임잡 전용 공개 API는 확인되지 않았다. 잡코리아 API는 `-94` §3.2에서 이미 **신입공채로 범위가 고정돼 `AF1`(경력·직무별 기술 수요 집계) 목적을 충족하지 못한다**고 판정했다. 같은 법인이므로 이 판정이 그대로 이어진다.

## 4. 링커리어 — 약관이 크롤링을 명시적으로 금지

이용약관(`linkareer.com/terms`)에 세 조항이 있다.

| 조항 | 원문 |
|---|---|
| 제20조 | "정상적인 서비스 흐름을 벗어나 기술적 조작·**크롤링·스크래핑** 등 비정상적 방식으로 자료를 수집하는 행위" |
| 제16조 | "**자동 접속 프로그램** 등을 사용하는 등 정상적인 용법과 다른 방법으로 서비스를 이용" |
| 제39조 | "**자동화 프로그램·매크로** 등 기계적 수단을 이용하여 서비스에 접근하거나 게시물을 작성·전송하는 행위" |

제20조는 '크롤링'과 '스크래핑'을 **단어 그대로 적어 금지**한다. 해석의 여지가 없다.

`robots.txt`는 참고로 기록한다. **판정에는 영향이 없다.**

```text
User-agent: *
Allow: /
Disallow: /stem/learn/api ... (learn 하위 및 로그인 사용자 영역)

User-agent: bingbot
Crawl-delay: 1
(동일 Disallow 목록)

Sitemap: https://linkareer.com/sitemap/sitemapindex.xml
```

`Allow: /`이고 공고 경로는 `Disallow`에 없다. **`robots.txt`와 약관이 정면으로 어긋나는 사례다.** 이때 무엇을 따를지는 `-94`가 이미 정해뒀다 — 기준 A는 "판례·**약관**상 금지"를 포함하므로 약관이 우선한다.

사람인 수집기가 `robots.txt`의 허용 경로만 요청하고 금지 경로를 회귀 테스트로 막아둔 것과 같은 원칙이며, 여기서는 그 위층인 약관에서 이미 걸린다.

## 5. 자소설닷컴 — 판정 불가

`robots.txt`는 공고 경로를 막지 않는다.

```text
User-agent: *
Disallow: /crt/*  /core  /rocket_correction  /coach-sellers  /webview/  /demo/
Allow: /
Sitemap: https://jasoseol.com/sitemap.xml
```

**그러나 이것으로 판정하지 않는다.** §4의 링커리어가 정확히 같은 모양이었고 약관에서
걸렸다. `jasoseol.com/terms`와 `/business/users/terms` 모두 SPA라 서버 응답에 약관
본문이 없어 확인하지 못했다.

기준 A는 OR 조건이므로 **약관을 읽지 못하면 통과 판정을 낼 수 없다.** 현재 상태는
"가능하다"가 아니라 "모른다"이며, 판정하려면 사람이 브라우저로 약관을 열어
회원의 의무·서비스 이용 제한 조항을 확인해야 한다.

별도로 목적 적합성에도 의문이 있다. 이 서비스는 스스로를 "대기업, 공기업 맞춤 채용"으로
소개하는 자기소개서 플랫폼이다. `-94` §3.2가 잡코리아 API를 배제한 근거가
**"신입공채로 범위가 고정되면 경력·직무별 기술 수요 집계라는 `AF1`의 목적을 충족할 수
없다"** 였는데, 같은 구조가 예상된다. A를 확인하는 수고를 들일 가치가 있는지 먼저
따질 만하다.

## 6. 공공데이터 채용 API — 기준 A 통과

### 6.1 잡알리오는 크롤링 대상이 아니다

`job.alio.go.kr`은 재정경제부 공공기관 경영정보 공개시스템(알리오)의 웹 화면이다.
같은 데이터를 공공데이터포털이 Open API로 공식 제공하므로, **정식 경로가 있는데
크롤링하는 선택은 기준 A의 취지에 어긋난다.** `job.alio.go.kr/robots.txt`는 404다.

### 6.2 API 계약

[재정경제부_공공기관 채용정보 조회서비스](https://www.data.go.kr/data/15125273/openapi.do)

| 항목 | 값 |
|---|---|
| 제공기관 | 재정경제부 |
| **이용허락범위** | **제한 없음** |
| 활용신청 | 개발단계 **자동승인** / 운영단계 심의승인 |
| 한도 | 개발계정 일 1,000회. 운영계정은 활용사례 등록 후 증액 신청 |
| 형식 | JSON + XML |
| 인증 | 공공데이터포털 회원가입 + 인증키 |

**기준 A 통과다.** 정식 수집 경로가 존재하고 이용허락범위에 제한이 없다. 크롤링이
아니라 API이므로 게임잡·링커리어에서 걸린 약관 문제가 발생하지 않는다. 워크넷이
공공데이터 경로로 통과한 것과 같은 구조다.

### 6.3 그러나 기준 B가 의심된다

A를 통과했으므로 B를 볼 수 있다. 응답 항목은 다음과 같다.

```text
공시 제목 · 접수기간 · 채용직무 및 인원 · 채용 전형 단계
접수방법 · 첨부 파일 메타정보
```

**자격요건도 기술스택도 없다.** "채용직무 및 인원"은 `전산직 3명` 수준이고 상세
요강은 첨부파일에 있다. 공공기관 채용 상세는 대부분 PDF/HWP이므로 기술을 추출하려면
그 파일을 파싱해야 하는데 두 가지가 걸린다.

- 수집기 이미지에 PDF/HWP 파서가 없다. `collector/gharchive/sinks.py`가 기록한 대로
  slim Python 런타임이며 Parquet writer조차 없다.
- `-99`가 `IMAGE_ONLY` 본문 상태를 두고 **권한 없는 OCR을 수행하지 않는다**고 정했다.
  첨부파일 파싱도 같은 계열의 판단이 필요하다.

구조적으로도 §5에서 자소설닷컴에 지적한 것과 같다. 범위가 공채로 고정되면 `AF1`의
경력·직무별 기술 수요 집계 목적과 어긋난다.

### 6.4 확인 방법

개발계정이 자동승인이므로 신청 즉시 키가 나온다. 표본 몇 건으로 "채용직무" 필드에
기술이 들어오는지, 첨부파일 없이 쓸 수 있는지가 판가름난다. `-161`(사람인·워크넷
API 신청)에 묶어 함께 신청하는 것이 효율적이다.

**이 문서는 A 통과까지만 기록한다.** 실제 채택 여부는 표본 확인 후 결정한다.

## 7. 측정하지 않은 것

**기준 A 미통과 대상(게임잡·링커리어)에 한해** `-94` §4의 "A에 걸리면 B·C를
측정하지 않는다"를 따랐다.

- 두 사이트의 기술 Coverage, 공고당 평균 기술 수 (기준 B)
- source별 분모 분리 영향 (기준 C)
- 실제 목록·상세 페이지 요청 — **두 사이트에 수집 목적의 HTTP 요청을 한 건도 보내지 않았다.** `robots.txt`, 공개 약관 페이지, 회사 정보 푸터만 조회했다.

수집 정당성이 없는 대상에 Coverage를 재보는 것 자체가 `-94` §2가 "수행하지 않을 것을 권고"한 행위다.

## 8. 결론과 후속

- **게임잡·링커리어 모두 기준 A 미통과.** `-149` 종결 유지.
- 채용공고 source는 **워크넷·사람인 2종으로 확정**한다. `-94` §3.3의 "정식 라이선스 경로를 가진 source 2개"와 일치한다.
- 두 곳을 수집하려면 기준 A를 통과할 경로 — 게임잡은 웍스피어와의 데이터 제공 계약, 링커리어는 약관 예외 서면 동의 — 를 먼저 확보해야 한다. 기술적 우회는 `-94`가 이미 배제한 선택지다.
- **자소설닷컴은 판정 불가**다. 약관을 확인하기 전까지 가능하다고 보지 않는다.
- **공공데이터 채용 API는 기준 A를 통과했다.** 다만 응답에 자격요건·기술스택이 없어
  기준 B 확인이 남는다. `-161`에 묶어 개발계정을 신청하고 표본으로 판단한다.
- 사이트를 늘리기 전에 먼저 볼 것이 두 가지 있다. 2026-09-08 워크넷 60일 백필
  4,631건에서 **기술 멘션이 있는 공고가 394건(8.5%)** 이었다. `-94` 기준 B의
  "Coverage < 60%면 제외 후보"에 워크넷 자체가 크게 못 미친다. source를 늘려도 이
  비율은 오르지 않으므로, `-146`의 source별 분모 분리와 `-143`의 Registry 누락을
  먼저 해결해야 한다.
- `-94` §7 후속 과제 5번("각 source에 기준 A 적용")은 이 문서로 게임잡·링커리어·
  자소설닷컴·잡알리오·공공데이터 API까지 충족한다.
